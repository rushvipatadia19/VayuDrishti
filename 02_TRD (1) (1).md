# 02. Technical Requirements Document (TRD)

**Owner:** Vaidehi · Updated for the air-quality case system. Build window is about 5 hours.
**Decided stack:** Supabase (Postgres) + `data/seed.json` fallback · Cloudinary for images · pretrained Hugging Face model for the AI explanation. Versions and model names below must be re-checked with the checklist in §2.

## §1 Stack

| Layer | Choice | Notes |
| --- | --- | --- |
| Runtime | Node 24 LTS | |
| App | Next.js 16 (latest 16.x patch), React 19, TypeScript strict, App Router | single app; backend = Route Handlers |
| Styling | Tailwind CSS 4 | CSS-first config (`@theme` in `globals.css`); no `tailwind.config.ts` |
| Validation | Zod 4 | all API inputs |
| Data | **Supabase (Postgres) with `data/seed.json` as read-only fallback** | case history must persist; tables in `08_DATABASE_DESIGN.md`. Real readings come from the Kaggle "Air Quality Data in India" daily city file (free Kaggle login to download), loaded into the seed once |
| Images | **Cloudinary** (unsigned upload preset) | optional evidence photo; only the returned `secure_url` is stored in the database |
| AI | **Pretrained model from Hugging Face, called through Inference Providers** (`https://router.huggingface.co/v1/chat/completions`, OpenAI-compatible) | no training or fine-tuning; model name in `HF_MODEL` |
| Analysis (no model) | plain TypeScript in `lib/analysis.ts` | rolling z-score, simple forecast, threshold check |
| Charts | Recharts | readings chart with baseline band and forecast; current-vs-limit bar and z-score gauge |
| Map | Leaflet (`react-leaflet` or plain Leaflet loaded client-side only) + OpenStreetMap tiles | dashboard India map; use `CircleMarker` pins (avoids the marker-icon bug); show the OSM attribution |
| Hosting | Vercel | deploy a hello-world by 0:45 of the build |
| UI generation | Google Stitch → exported code → our components | Diva |
| Coding agent | Antigravity (reads `AGENTS.md`) | Shreya (backend), others as needed |

**What the AI does and does not do:** the pretrained model only writes the plain-language explanation (applicable standard, what it means, suggested next step) from data we pass in. It never decides whether a limit is exceeded and never supplies a threshold. Those come from code and the `standards` seed.

## §4 Security (what fits in a sprint)

| Threat | Mitigation |
| --- | --- |
| Leaked key | server-only env vars; `.env.local` in `.gitignore`; check `git log --oneline -- .env.local` prints nothing |
| Bad input / injection | Zod `safeParse` on every body; length cap (2000 chars) on anything sent to the model |
| XSS | React escapes by default; render AI output as text, or sanitize with DOMPurify |
| Personal data in prompts | send only readings, station and standard data; never names or contact details, since prompts go to a third-party inference provider |
| Image uploads | unsigned preset limited to images and a size cap; store only the URL; render with `next/image` or a plain `img` with alt text |
| Secrets in logs | no `console.log` of keys or tokens |
| Accounts | none for the demo ("Continue as demo user" at most) |

## §5 Performance targets

| Endpoint type | Target p95 | Max |
| --- | --- | --- |
| Simple read | 100 ms | 300 ms |
| Write with validation | 200 ms | 500 ms |
| Analysis (code only) | 100 ms | 300 ms |
| Explanation, cache hit | 50 ms | 150 ms |
| Explanation, cache miss (HF call) | 3 s | 8 s, then fallback text |

Show a skeleton for anything over 300 ms. Never show a spinner longer than 5 s in the demo.

## §6 Architecture decisions (also the answers to technical judge questions)
- **ADR-1 One Next.js app:** one repo, one deploy, no CORS or cookie problems.
- **ADR-2 Data:** Supabase because case history (actions and status changes) must persist and writes to JSON do not persist on Vercel. `data/seed.json` is the read-only fallback and holds stations, readings and the standards snippets.
- **ADR-3 Hugging Face pretrained model:** a hosted open model needs no training and no GPU on our side; the model name is an env var so we can swap it. It only explains; it does not decide.
- **ADR-4 Deterministic compliance:** the anomaly flag, forecast and threshold check run in TypeScript, so every flag is reproducible and explainable.
- **ADR-5 AI cache:** committed `data/ai-cache.json` plus an in-memory `Map`; this also protects us from the small HF free-tier credit.
- **ADR-6 Cloudinary:** images are optional evidence; offloading storage avoids building file handling.
- **ADR-7 Vercel:** zero-config GitHub deploys, HTTPS by default.
- **ADR-8 Stitch + Antigravity:** speed; every agent-written file is run and reviewed by a human before merge.

## §7 Reliability

| If this fails | Do this |
| --- | --- |
| HF error, timeout or credit limit | cached answer; else rule-based fallback text built from the standard and threshold results (never a 500 on the demo path) |
| Supabase | fall back to `seed.json`; toast "Showing demo data" |
| Cloudinary upload | the report still submits without the image; show a small notice |
| Deploy | roll back to last green deploy in Vercel |
| No Wi-Fi | phone hotspot; localhost as last resort |
| White screen | `app/error.tsx` and `app/not-found.tsx` exist and look presentable |

## §8 Next.js 16 gotchas
- `params`, `searchParams`, `cookies()`, `headers()` are async: `const { id } = await params`.
- `middleware.ts` is now `proxy.ts` (we likely need neither).
- Turbopack is the default bundler. Run `npm audit`, take the latest 16.x patch before the final deploy.
